## 1. 结论速览

已验证成立：

- Flutter/Android 链完整：Flutter 3.44.6 + Dart 3.12.2，与 Windows 侧 `E:\dev\flutter` 版本完全一致。
- Rust 交叉编译成立：WSL 产出 aarch64 的 `libndk_smoke.so`（ELF 64-bit LSB shared object, ARM aarch64）。
- Flutter 出包成立：debug APK 构建成功（140 MB，耗时 8 分 29 秒）。
- Windows x64 链也已就绪并实测：Flutter 构建出 `fwin.exe`（38.6 秒）；Windows 侧 Rust（MSVC）编译并跑通单元测试，产出 PE32+ x86-64 DLL。
- WSL 内有可运行目标：Android 模拟器 `diary36`（API 36，x86_64）70 秒内启动完成，`flutter devices` 能识别。

尚未成立：

- Android 真机未连接；arm64 真机验收仍无路径。
- Linux 桌面缺 `clang` 与 `libgtk-3-dev`（`sudo` 需要密码，自动化装不了）。
- 两侧 Rust 版本不一致（WSL 1.98.1、Windows 1.94.1），需要在工程里约束，否则同一个 `Cargo.lock` 可能在一侧编不过。

## 5. 缺口与需要决定的事

### 5.1 运行目标

可用的和缺的：

| 选项 | 状态 | 能做到什么 |
|---|---|---|
| Android 模拟器（WSL） | 已就绪，`emulator-5554`，70 秒启动 | 能跑 Android 功能闭环。**x86_64 镜像不等于验收要求的 arm64 真机**，只能当开发手段 |
| Linux 桌面（WSL） | 需要 `sudo apt install -y clang libgtk-3-dev`（当前 sudo 需要密码，自动化装不了） | WSL 里最快的迭代目标；不能代替真机验收 |
| Windows 桌面（Windows 侧） | 已就绪，`flutter devices` 已列出 Windows/Chrome/Edge | 能满足"Windows x64 可用"这一半验收；录音与移动端行为另说 |
| Android 真机（arm64） | 未连接 | 唯一能满足 arm64 真机验收的路径 |

### 5.2 两侧 Rust 版本不一致

| 侧 | 版本 | 已装目标 |
|---|---|---|
| WSL | 1.98.1 | `x86_64-unknown-linux-gnu`、`aarch64-linux-android`、`x86_64-linux-android` |
| Windows | 1.94.1 | `x86_64-pc-windows-msvc`（另有 gnu 工具链） |

处理方式二选一，在 B0 建 `Cargo.toml` 时定：

1. 在 workspace 里写 `rust-version = "1.94"`，以低版本为准，两侧都能编。
2. 把 Windows 侧 `rustup update` 到与 WSL 一致，用新特性。

推荐第 1 种：CI 与本地更容易对齐，升级可以单独做一次。

### 5.3 其他

- `rustup target add armv7-linux-androideabi` 在 WSL 报组件冲突，未安装。计划只要求 arm64，暂不处理。
- Linux 桌面到目前为止只是"编译链可用"，没有实际构建过 Linux 产物。
- Windows 侧的 Rust 与 Flutter 都能从 WSL 通过 `cmd.exe /c` 驱动，但路径要写成 Windows 形式（`E:\...`），`.bat` 不能直接执行。

## 6. 对验收计划的影响

本环境能独立覆盖的：编译与打包（两端都有了）、纯逻辑与数据层用例（如重复提交、状态机、错误归一化）、Windows 桌面上的界面与交互用例、以及基于主机 x86_64 的算法正确性验证。

必须等真机才能做的：录音相关（权限拒绝、首帧、长录音暂停锁屏、来电与设备切换、进程被杀恢复）、系统字体与窄窗口、真机性能预算、锁屏与后台调度。验收计划 E10–E14、E29、E37 都属于这一类，**不得用模拟器或 Windows 桌面结论替代**。
