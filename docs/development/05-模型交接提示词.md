# 分模型交接提示词

两个模型在不同任务/分支中工作。建议从同一基础版本开始，分别使用 frontend 和 backend 工作分支。先共享本目录全部文档，再分别发送下面对应的说明。以下说明供后续开发使用，本次计划编写不启动开发。

## 给前端模型

你负责“不写日记”的前端与平台适配开发。请先阅读 docs/development/00-开发总览.md、01-共享接口契约.md、02-前端开发任务书.md、04-验收与测试计划.md。产品要求已经在这些文件中确认，不要重新发散成社交平台、普通聊天机器人或云端网站。

首版目标为 Windows x64 和 Android arm64 上的单设备应用。建议栈为 Flutter/Dart，后端由另一个模型实现为 Rust 本地核心。你的任务是记录、日记阅读、搜索、来源查看、版本、设置、插件管理和备份恢复界面，以及原生录音、文件选择/分享/拖放、播放、系统凭据和后台唤醒。

请遵守目录所有权：你负责 apps/diary_app、packages/platform_host、packages/diary_mock、tests/e2e；不要自行改 crates、共享 DTO 或桥接生成文件。接口缺口提交给后端，由其更新契约和类型包。应用工程及其依赖锁文件由你维护，后端通过变更清单请求接入。

用户最重视打开快、立即能记、可靠保存和舒服的长时间倾诉。默认安静记录，主动请求时才回应。AI 日记正文必须是简洁、有感染力、忠于事实的自然段，不能显示为要点总结。所有“已保存”“正在录音”“已完成整理”状态必须来自真实确认。

先做 F0/F1 的可行性验证及 Mock 页面，再按任务书逐步推进。Mock 与真实实现共用 DiaryApi；尽早联调首个真实保存和录音闭环。录音不得依赖页面存活，Android 需验证锁屏和系统中断；大文件与长音频不能整体读进内存。

请先交付你的执行顺序、环境检查和 M0 验证结果，再完成实际开发。遇到未冻结选型，以目标设备测量和文档依据作决定并记录；不要自行更换整体技术栈或降低产品范围。每阶段提供已完成内容、真实/Mock 接入状态、测试结果和需要后端处理的问题。没有实机或构建条件时如实标注，不把未验证功能报告为完成。

## 给后端模型

你负责“不写日记”的本地后端开发。请先阅读 docs/development/00-开发总览.md、01-共享接口契约.md、03-后端开发任务书.md、04-验收与测试计划.md。后端在用户设备内运行，不建设必须部署的云业务服务器。

首版目标是 Windows x64 与 Android arm64。建议使用 Rust 本地核心、SQLite、独立原件文件库、内置小型向量模型及嵌入式检索，通过 flutter_rust_bridge 对接 Flutter。你负责存储、原件/录音片段接收、解析、关键词和向量混合检索、模型服务适配、自动整理、版本、持久队列、插件宿主、备份与恢复。

你负责 crates/diary_core、crates/diary_bridge、packages/diary_api、packages/diary_bridge、models/manifest、plugins/examples、共享测试资料与架构决定。先提供与 Rust 内部实现无关的 Dart DTO 和 DiaryApi，使前端可以独立开发 Mock。不要编辑前端页面和平台工程；打包依赖通过清单交给前端合入。

最重要的规则：记录不等待模型/网络/索引；原件不被 AI 或插件覆盖；日记修改保留版本；自动生成不覆盖人工修改；默认不回应倾诉；搜索覆盖原文和日记且能定位来源；队列失败不影响原件。日记允许润色，但正文必须自然段、简洁、有感染力并忠于事实。

先完成 B0，验证两个目标平台上的桥接、本地模型、中文短词搜索和插件运行候选，冻结契约和依赖。模型候选及性能数字尚未实测，不应当成已证明的事实。之后按 B1 至 B8 推进，每阶段给前端一个可调用的真实闭环。M1 开始联调，不把接口对接拖到最后。

插件接口需要真实可安装的示例、权限与执行预算，不能只留空函数。搜索需要验证中文口语与短词，不能只拿几条英文样例演示。录音由前端平台层采集，你提供可恢复的交接协议；后台任务入口不能依赖页面对象。

请先报告环境检查、执行顺序及 M0 结果，再完成开发。每阶段附接口/数据版本、实际测试、构建产物、性能测量和已知限制。没有实际运行的部分明确标记，不能使用固定假输出代替 AI 或真实持久化。

## 两个模型的协作约定

共享契约由后端维护，前端对变更做调用方审核。每次变更写明动机、字段/行为变化、是否兼容、需要前端调整什么，并提供更新后的场景样例。前端不能私自补写数据库；后端不能绕开平台层直接接管界面。

每阶段交换的交付信息固定为：提交/构建版本、完成任务编号、接口版本、运行方式、测试结果、未解决问题、需要另一方接入的内容。缺陷定位优先用最小复现和真实输入状态，不凭猜测相互修改对方目录。

首个集成目标只有一条完整路径：前端输入一句话，核心持久化，关闭重开仍在，离线关键词搜索能找到。第二条路径是长录音保存与恢复。接着加入本地语义检索，最后接入远端整理和扩展能力。界面完整度不能替代这些真实闭环。

最终由前端负责整体应用打包，后端提供可复现核心与模型资源。双方按验收计划共同确认发布；遇到缺少凭据、实机或其他外部条件时，标出未验证范围并完成其余独立工作，不伪造通过结论。
